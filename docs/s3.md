# S3 backend (`vcs-store-s3`)

`vcs_store_s3::S3Backend` implements `vcs_remote::Backend` for S3-compatible object stores.

## Required provider capabilities

- Strong read-after-write for new keys.
- Range `GET`.
- `PUT` with `If-None-Match: *` (create-only) that returns 412 (or 409) when the key exists.
- `PUT` with `If-Match: <etag>` (compare-and-swap) that returns 412 (or 409) on mismatch.
- `ListObjectsV2` with continuation tokens.
- Path-style addressing over plain `http://` (use a TLS-terminating proxy for HTTPS).

`S3Backend::connect` probes a scratch key (`<prefix>.vcs-probe/<nonce>`) to check that both
conditional primitives are enforced, deletes it, and refuses the provider otherwise. Use
`new_unchecked` only if you have verified the provider yourself.

Error mapping: 5xx, 408, 429, timeouts and connection failures become
`BackendError::Unavailable`; 412/409 on conditional PUTs become `Ok(false)` / `Ok(None)`.

## Running the MinIO tests

```sh
docker run -d --name vcs-minio -p 9000:9000 \
  -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin \
  quay.io/minio/minio server /data

VCS_TEST_S3_ENDPOINT=http://127.0.0.1:9000 cargo test -p vcs-store-s3

docker rm -f vcs-minio
```

Optional variables: `VCS_TEST_S3_BUCKET` (default `vcs-test`, created if missing),
`VCS_TEST_S3_ACCESS_KEY` / `VCS_TEST_S3_SECRET_KEY` (default `minioadmin`). Each test uses a
unique key prefix. Without `VCS_TEST_S3_ENDPOINT` the MinIO tests skip; the fake-server tests
(probe refusal, error mapping) always run.
