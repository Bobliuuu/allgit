# S3 backend (`vcs-store-s3`)

`vcs_store_s3::S3Backend` implements `vcs_remote::Backend` for S3-compatible object stores.

## Required provider capabilities

- Strong read-after-write for new keys.
- Range `GET`.
- `PUT` with `If-None-Match: *` (create-only) that returns 412 (or 409) when the key exists.
- `PUT` with `If-Match: <etag>` (compare-and-swap) that returns 412 (or 409) on mismatch.
- `ListObjectsV2` with continuation tokens.
- Path-style addressing over plain `http://` (use a TLS-terminating proxy for HTTPS).

`S3Backend::connect` probes a scratch key (`<prefix>.vcs-probe/<nonce>`) to check that both
conditional primitives are enforced, deletes it, and refuses the provider otherwise. Use
`new_unchecked` only if you have verified the provider yourself.

Error mapping: 5xx, 408, 429, timeouts and connection failures become
`BackendError::Unavailable`; 412/409 on conditional PUTs become `Ok(false)` / `Ok(None)`.

## Using an S3 bucket from the `vcs` CLI

```sh
export AWS_ACCESS_KEY_ID=minioadmin AWS_SECRET_ACCESS_KEY=minioadmin
vcs remote set 's3://my-bucket/team/repo?endpoint=http://127.0.0.1:9000&region=us-east-1'
vcs publish
vcs clone 's3://my-bucket/team/repo?endpoint=http://127.0.0.1:9000' work
```

URL form: `s3://<bucket>[/<prefix>]?endpoint=<http://host:port>[&region=<name>]`.

- `endpoint` is required and must be plain `http://host:port` (percent-escapes are decoded).
  **TLS is not supported yet**, so `https://` endpoints and AWS S3 itself cannot be used
  directly; front them with a TLS-terminating proxy or use a local gateway such as MinIO.
- `region` defaults to `AWS_REGION`, then `AWS_DEFAULT_REGION`, then `us-east-1`.
- The bucket must already exist; the CLI never creates it.
- Credentials come only from `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`. If either is
  missing the command fails with an error naming the variable. `AWS_SESSION_TOKEN` is not
  supported yet.
- `.vcs/remote` stores the URL exactly as given, so it holds the bucket, prefix and endpoint
  but never a secret. Any other query option (for example a pasted `secret_key=`) is rejected
  and its value is not echoed in the error.
- Connecting probes the provider for conditional-write support and refuses it otherwise.

## Running the MinIO tests

```sh
docker run -d --name vcs-minio -p 9000:9000 \
  -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin \
  quay.io/minio/minio server /data

VCS_TEST_S3_ENDPOINT=http://127.0.0.1:9000 cargo test -p vcs-store-s3 -p vcs-cli

docker rm -f vcs-minio
```

Optional variables: `VCS_TEST_S3_BUCKET` (default `vcs-test`, created if missing),
`VCS_TEST_S3_ACCESS_KEY` / `VCS_TEST_S3_SECRET_KEY` (default `minioadmin`). Each test uses a
unique key prefix. The CLI test `s3_minio_remote_workflow` runs the full publish/clone/fetch/sync/diverge workflow and checks that the secret never reaches `.vcs/`. Without `VCS_TEST_S3_ENDPOINT` the MinIO tests skip; the fake-server tests
(probe refusal, error mapping) always run.
